# Explicit reviewed draft fixture and cited output approval

Date: 2026-10-22. Branch: `mvp-reviewed-draft-fixture`. Parent: draft PR [#150](https://github.com/Kokfu/congenial-potato/pull/150), commit `3f436bd2473f7d624a887e03d1e9188984f02ec1`.

## Behavior and scope

Ordinary dispatch remains blocked for document-plan tasks. A separate owner/CSRF-protected `draft-fixture` route requires the exact admitted plan hash, resolves the reviewed assignment server-side, and admits only an unpriced text fixture (`fixture`, `fixture-alpha` or `fixture-beta`). It rechecks plan status/hash/scope, original source/context, current grants, task assignment, configuration, backlog status and dependencies before creating execution/budget/outbox records atomically.

The new run stores its plan identity, pins the reviewed brief revision/digest, and copies the exact prepared source message/hash from the Manager run. Later project notes are intentionally not substituted: the UI displays the reviewed source revision before the explicit request. New root IDs and pinned agent configurations use the existing worker path. Concurrent or repeated requests cannot create a second run for the same queued task.

The text fixture returns a deterministic **Synthetic document draft**, bounded to 1,800 characters. It quotes a bounded JSON-escaped source excerpt, identifies unknown facts, and records [S1], project/brief revision/full-source digest, prepared-context digest and exact reviewed plan identity/hash. This is not substantive model-written analysis or citation-quality evaluation. Structured/tool/native/paid configurations cannot use this path.

Generation, completion and exact artifact approval/persistence recheck the recorded plan/source/context and fresh effect authority. A changed adapter result cannot become a draft approval. Saved-artifact reads verify the deterministic references against historical identity without treating later grant revocation as deletion of accepted owner history. These records share the replaceable application database; they are not independent attestation or external-truth guarantees.

Artifact approval and task acceptance remain separate owner actions. After the exact artifact is applied, **Accept reviewed draft task** verifies a saved artifact from the reviewed draft run before completing the task. Unresolved or rejected output cannot release dependencies. Each dependent task still requires its own explicit request; admission never automatically launches plan work.

## Limits and next task

The plan remains predefined fixture JSON configured through the existing API; a guided local document-fixture setup is the next usability increment. The draft is a deterministic quote/provenance demonstration, not autonomous analysis, fact checking or substantive document creation. It preserves the reviewed source, not later notes, and does not authorize arbitrary tools or external effects. Existing fixtures do not establish physical durability, protected recovery, exactly-once external delivery or unknown-charge guarantees.

No full backend/witness/launcher acceptance or actual owner Windows Docker Desktop hosting is claimed. Paid/live activation, product external dispatch, real effects, production connections, public deployment and merges remain disabled. Protected credentials, independently verified pricing, caps/cancellation and unknown-charge handling remain prerequisites for separately authorized live activation.
